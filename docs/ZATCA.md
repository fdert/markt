# الربط مع هيئة الزكاة والضريبة والجمارك (فاتورة)

## المراحل
| المرحلة | ما المطلوب | الحالة في رصيد |
|---|---|---|
| الأولى: الإصدار (منذ 4 ديسمبر 2021) | فاتورة إلكترونية + رمز QR بخمسة حقول (TLV) | مفعّلة تلقائياً لكل الفواتير |
| الثانية: الربط والتكامل (منذ 1 يناير 2023) | XML بصيغة UBL 2.1، توقيع رقمي XAdES، رمز QR بتسعة حقول، عدّاد ICV وسلسلة PIH، الإبلاغ والاعتماد عبر واجهات الهيئة | مكتملة لكل فرع |

لا توجد «مرحلة ثالثة» مستقلة؛ المرحلة الثانية تُطبَّق على **موجات** متتالية حسب حجم الإيرادات، وتُبلَّغ كل منشأة بموعدها قبل 6 أشهر على الأقل.

## خطوات ربط الفرع (الإعدادات ← الضريبة)
1. **رمز التحقق (OTP):** من بوابة فاتورة. في بيئة المطوّرين الرمز ثابت `123345`.
2. **طلب شهادة الامتثال:** ينشئ رصيد مفتاح secp256k1 وطلب شهادة (CSR) بالقالب `TSTZATCA/PREZATCA/ZATCA-Code-Signing` ثم يستدعي `POST /compliance`.
3. **فحص الامتثال:** يرسل 6 مستندات موقّعة إلى `/compliance/invoices` (فاتورة، وإشعار دائن، وإشعار مدين؛ ضريبية ومبسّطة) حسب نوع الشهادة (1100 / 1000 / 0100).
4. **شهادة الإنتاج:** `POST /production/csids` ثم يبدأ التوقيع والإرسال.
5. **التشغيل:**
   - المبسّطة: `/invoices/reporting/single` (خلال 24 ساعة).
   - الضريبية: `/invoices/clearance/single`، ويُحفظ المستند المختوم الذي تعيده الهيئة. عند الرد 303 يتحول الإرسال إلى الإبلاغ.
   - الفواتير المعلّقة (أخطاء الشبكة أو 5xx أو 429) تُعاد كل 5 دقائق تلقائياً.

## ما الذي راجعناه مقابل المشاريع المرجعية
| البند | المرجع | النتيجة |
|---|---|---|
| بصمة الفاتورة | ملف `invoice.xsl` داخل SDK الهيئة، ثم C14N11 | **أُصلح خطأ**: المسافات المتبقية بعد حذف العناصر لم تكن محسوبة |
| بصمة SignedProperties | سلوك SDK الرسمي | **أُصلح خطأ**: وسم DigestMethod يجب أن يكون مغلقاً ذاتياً (`/>`) |
| مفتاح بيئة المطوّرين | ksa_compliance | **أُضيف**: الهيئة تعيد هناك شهادة ثابتة، فيُوقَّع بمفتاحها المعروف |
| وقت الإصدار ووسم QR رقم 3 | SDK | **عُدّل** إلى توقيت الرياض ليطابق IssueDate وIssueTime |
| الإشعار المدين (383) | optima_zatca، ERPGulf | **أُضيف** |
| التقريب النقدي للأعلى | قاعدة BR-KSA-EN16931-11 | **أُصلح**: يُكتب رسماً على البند مع رمز سبب (BR-KSA-20) |
| رد الاعتماد (clearedInvoice) | ksa_compliance، Salla | **أُضيف** حفظ المستند المختوم ورمز QR الجديد منه |
| الإعادة التلقائية للإرسال | ksa_compliance | **أُضيفت** |
| تهريب النصوص | C14N | لا تُهرَّب علامة التنصيص `"` داخل النصوص |

## الاختبارات
- `api/test/zatca.test.ts`: اختبارات وحدات لكل خوارزمية.
- `api/test/zatca-e2e.test.ts`: المسار كاملاً عبر خادم يحاكي بوابة فاتورة.
  - يشمل الربط ← الامتثال ← الإنتاج ← البيع ← الإبلاغ ← الاعتماد ← المرتجع ← إعادة المحاولة ← التقريب.
- **التحقق الرسمي:** عند ضبط `ZATCA_CLI` تُفحص كل فاتورة بأداة الهيئة الرسمية (SDK 238-R3.4.5).
  - تشمل الفحوص: XSD وEN16931 وقواعد KSA وQR والتوقيع وPIH.
  - النتيجة الحالية: كل المستندات **صالحة**.

```bash
bash tools/zatca-validator/setup.sh
cd api && ZATCA_CLI=$PWD/../tools/zatca-validator/zatca.sh npm test
```

## الفحص الحيّ مع الهيئة

```bash
docker compose exec api npx tsx scripts/zatca-live-check.ts 123345 sandbox
```
